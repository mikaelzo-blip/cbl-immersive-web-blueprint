# 04 — Homepage Architecture

Homepage should behave like a guided technical portfolio, not a long catalog.

## Section 01 — Immersive Mechanical Hero

Purpose:

- establish visual identity
- show technical depth immediately
- introduce CBL through a mechanical system story

Interaction:

- vertical sticky scrollytelling
- 3D gearbox/drivetrain remains visible
- narrative progresses through 4–5 stages
- no required horizontal scroll

Suggested story:

1. system overview
2. transmission relationship
3. inspection logic
4. field execution
5. handoff to real project imagery

## Section 02 — Company credibility

Quiet editorial section.

Use:

- concise company overview
- verified experience facts only
- project documentation framing

Avoid dashboard-style stat cards.

## Section 03 — Capability index

Present services as an indexed list/register.

Possible categories:

- electrical & automation
- mechanical systems
- pump & water
- HVAC
- lighting
- technical procurement

Each line can expose scope or selected work without becoming a card.

## Section 04 — Control Panel Technical Story

Second immersive moment, shorter than hero.

Story:

- cabinet overview
- door/open reveal
- HMI/PLC/drive hierarchy
- wiring/signal relationship
- testing/commissioning

## Section 05 — Selected Projects

Use real documentation.

Composition:

- one large featured case study
- supporting editorial rows
- project title, discipline, short scope, location/date only if verified

No uniform 3-column thumbnail card wall as primary layout.

## Section 06 — Pump / Water System Story

Use a cutaway/flow explanation.

Narrative:

- system role
- suction/discharge
- motor/shaft/impeller
- inspection/service logic

## Section 07 — Expertise / technical register

Structured detail for users who need more depth.

This can include specific equipment/components only where supported by company data.

## Section 08 — Work Process

Timeline rather than four floating cards.

Possible stages:

- survey / inspection
- planning / scope confirmation
- execution
- testing / commissioning
- documentation / handover

## Section 09 — Brand / technical ecosystem

Clean technical logo wall or partner/equipment ecosystem.

Only include brands that are actually supported by company/project data.

## Section 10 — Vendor / legal readiness

Document-register aesthetic.

Focus on trust and procurement readiness, not decorative certificates.

## Section 11 — Contact

Direct project inquiry.

Minimal content:

- contact method
- project discussion CTA
- optional form
- office/company details if verified

Do not finish the site with a giant gradient CTA box.
