# 04 — Homepage Architecture

Homepage should behave like a guided technical portfolio, not a long catalog.

## Current implementation phase: non-3D editorial

The current production redesign does **not** use new 3D assets. Use real CBL project photography, structured technical content, typography, whitespace, metadata, rules/borders, and restrained motion.

The earlier immersive 3D concepts remain future options only.

## Section 01 — Editorial project-led hero

Purpose:

- establish CBL as a technically credible contractor and project-based solution provider
- communicate scope without generic corporate slogans
- show authentic field evidence immediately

Composition:

- concise company/discipline label
- strong typography-first positioning
- one large authentic project image or intentionally composed real-photo sequence
- short supporting copy
- direct project inquiry + portfolio action
- restrained technical metadata

Avoid:

- floating cards
- pill/chip clouds
- decorative gradients/blobs
- fake metrics
- generic stock imagery
- decorative 3D

## Section 02 — Company credibility

Quiet editorial section.

Use:

- concise company overview
- verified experience facts only
- project documentation framing
- project-based specialist-network model where relevant

Avoid dashboard-style stat cards. If numbers are used, present them as typography/register data rather than four rounded metric cards.

## Section 03 — Capability index

Present services as an indexed list/register.

Current categories supported by company documentation:

- electrical & automation
- mechanical / conveyor systems
- pump / plumbing / water systems
- HVAC & refrigeration
- lighting / DMX
- technical procurement

Each row can expose scope, representative equipment, or selected work without becoming a repeated card.

## Section 04 — Selected projects

Use real documentation and make it the visual center of the homepage.

Composition:

- one large featured case study
- supporting editorial rows
- varied image proportions where the source photography supports it
- project title, discipline, short scope, unit/location/date only when appropriate and verified
- link to detailed case studies

No uniform 3-column thumbnail-card wall as the primary layout.

Good homepage candidates from verified material include electrical/automation work, conveyor/mechanical work, HVAC/VRF, lighting/show, and other projects with clear authentic photography.

## Section 05 — Technical capability / expertise register

Use structured detail for users who need more depth.

Can include specific equipment/components only where supported by company/project data, for example PLC/HMI/drive/soft starter, conveyor/bearing/shaft/gearbox, HVAC/refrigeration components, pumps/water systems, and lighting/DMX.

Use rows, columns, technical indices, or disclosure patterns rather than icon-card spam.

## Section 06 — Work process

Use an editorial timeline/process register rather than four floating cards.

Source process can be condensed from the verified project methodology:

- clarification / inspection
- planning / team selection
- procurement / verification where required
- mobilization / site readiness
- execution
- quality control / testing
- documentation / handover
- follow-up where contractually applicable

Homepage may group these into 5–6 stages for readability without inventing new claims.

## Section 07 — Why CBL / operating model

Explain the real operating model rather than generic benefit cards.

Potential themes supported by company documents:

- one point of coordination across a project cycle
- specialist personnel mobilized according to discipline/equipment/risk
- specification verification and documentation
- experience working in active operational facilities
- project records that can be traced to PO/SPK/BAST/delivery/documentation sources

Keep claims measured and source-based.

## Section 08 — Brand / technical ecosystem

Clean technical logo wall or equipment ecosystem.

Only include brands supported by actual project data. Brand appearance indicates project experience, not official distributorship unless separately proven.

## Section 09 — Vendor / legal readiness

Document-register aesthetic.

Focus on verifiable company status, procurement readiness, and traceability rather than decorative certificate cards.

Do not present SBU/SKK/ISO/SMK3 as active unless current evidence is available.

## Section 10 — Contact

Direct project inquiry.

Minimal content:

- project discussion CTA
- WhatsApp / phone / email
- office details when verified
- optional simple inquiry form

Do not finish the site with a giant gradient CTA box or a dashboard of contact cards.

## Rhythm rule

Adjacent sections should not reuse the same composition. Rotate deliberately between:

- typography-led editorial block
- large project photography
- indexed technical list
- process timeline/register
- quiet evidence/legal information

This variation should come from content hierarchy, not decoration.
